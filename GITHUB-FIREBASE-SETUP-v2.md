# Личный сеанс: GitHub → Firebase → iPhone

Комплект от 11 ноября 2026. Это устанавливаемое веб-приложение (PWA). В текущем комплекте доступны локальные записи и резервная копия; облачная синхронизация ещё НЕ подключена. Создание базы само по себе её не включает.

Предлагаемая схема: GitHub Pages публикует интерфейс, Firebase обеспечивает вход и хранение личных данных. Отдельно публиковать тот же сайт в Firebase Hosting не требуется.

## 1. Готовые файлы

Личные данные я уже подготовил из актуальной версии проекта: новых записей после неё ты не добавляла.

- `personal-cinema-github-v2.zip` — только интерфейс для GitHub, без твоих записей. Иконка № 2 «Кино с сердцем» уже выбрана; билет сохранён как запасной вариант.
- `personal-cinema-data.json` — личная резервная копия: 247 карточек, 55 постеров, отзывы, история просмотров и 4 подборки. JSON хранить у себя, НЕ загружать в GitHub.
- `GITHUB-FIREBASE-SETUP-v2.md` — эта инструкция.

Данные в JSON: «Новогоднее» — 34 истории, «Детство» — 3, «Любимые дорамы» — 14, «Фэнтези» — 16. Пустые и служебные записи импорта сохранены отдельно в importDrafts и не отображаются в кинозалах. Постеры включены внутрь JSON и не зависят от старого адреса сайта.

## 2. Создать репозиторий GitHub

1. Войди в https://github.com под нужным аккаунтом.
2. Нажми `+` → `New repository`.
3. Название: например, `personal-cinema`.
4. Для бесплатного GitHub Pages у личного GitHub Free репозиторий обычно должен быть `Public`. Мы публикуем пустой интерфейс, а не личный JSON. Если выбираешь Private, проверь поддержку Pages своим тарифом; сам сайт Pages также может оставаться публичным.
5. Добавь README, затем `Create repository`.
6. Распакуй `personal-cinema-github-v2.zip` двойным кликом.
7. В репозитории нажми `Add file` → `Upload files`.
8. Открой распакованную папку и перетащи её СОДЕРЖИМОЕ, сохранив папку `icons`. Не загружай сам ZIP и не добавляй ещё один внешний уровень папки.
9. В корне должны находиться `index.html`, `iphone.css`, `manifest.webmanifest`, `service-worker.js`, `icons.html` и папка `icons`.
10. Нажми `Commit changes`. Если браузер не перенёс скрытый файл `.nojekyll`, для этого комплекта без подчёркиваний в путях это не препятствует запуску.

## 3. Включить адрес приложения

1. Внутри репозитория открой `Settings` → `Pages`.
2. В `Build and deployment` выбери `Source: Deploy from a branch`.
3. В `Branch` укажи `main`, папку `/(root)`, затем `Save`.
4. Дождись успешной публикации; вкладка `Actions` показывает процесс. Обнови `Settings` → `Pages` и открой выданную ссылку через `Visit site`.
5. Сначала коллекция должна быть пустой. Это ожидаемо.
6. На новом адресе нажми внизу «Восстановить» и выбери готовый `personal-cinema-data.json`. Подтверди замену пустой коллекции. На этом этапе данные будут только в браузере этого устройства; это ещё не облачная синхронизация.

Обычный формат адреса — `https://ИМЯ.github.io/personal-cinema/`. Используй фактическую ссылку из Pages.

## 4. Подготовить Firebase

Рекомендация: тот же Google-аккаунт, где Gift Planner, но НОВЫЙ отдельный проект для кино. Так данные и бесплатные квоты не смешиваются. Использование общей базы планировщика тоже возможно, но сначала нужны её текущие Rules и конфигурация; инструкции ниже по замене Rules относятся только к новому проекту.

1. Открой https://console.firebase.google.com и выбери нужный Google-аккаунт справа вверху.
2. `Create a project` / `Add project` → название, например, `personal-cinema`. Google Analytics для этого трекера необязателен; можно отключить.
3. Оставь бесплатный план `Spark`. Не подключай оплату или Cloud Storage ради запуска этой версии.
4. В обзоре проекта нажми значок веб-приложения `</>`; имя — `Личный сеанс`; затем `Register app`. Для PWA регистрируется веб-приложение, не iOS-приложение.
5. Firebase Hosting здесь не выбирай: интерфейс уже размещён на GitHub Pages.
6. На шаге настройки SDK найди объект `const firebaseConfig = { ... };`. Скопируй его целиком. Если закрылось окно: шестерёнка → `Project settings` → `General` → `Your apps` → нужное Web app → `SDK setup and configuration` → `Config`.
7. Пришли этот объект и фактическую ссылку GitHub Pages в чат. Это клиентская конфигурация. Пароль Google, пароль приложения и файлы Service Account / private key не нужны и присылать их не следует.

## 5. Включить вход

1. Firebase → `Build` → `Authentication` → `Get started`.
2. `Sign-in method` / `Sign-in providers` → `Email/Password` → включи обычный Email/Password → `Save`. Вход по ссылке включать не надо.
3. `Users` → `Add user` → создай свой email и пароль. Пароль сохрани у себя, в чат его не присылай.
4. Скопируй `User UID` созданного пользователя. Он нужен для ограничения доступа только твоей учётной записью.
5. В `Authentication` → `Settings` → `Authorized domains` добавь домен своего Pages: например `ИМЯ.github.io`. Без `https://` и без `/personal-cinema/`.

## 6. Создать базу

1. `Build` → `Firestore Database` → `Create database`.
2. Нужен Cloud Firestore, не Realtime Database и не Data Connect.
3. Если предложен выбор редакции — `Standard`; Database ID — `(default)`.
4. Выбери регион. Учти, что просто поменять его потом нельзя.
5. Режим доступа — `Production mode`. Не Test mode.
6. Заверши создание. Вручную добавлять фильмы и коллекции не нужно.
7. Пока синхронизация не подключена, оставь закрытые production-правила. После получения конфигурации и UID я подготовлю подходящие правила вместе с кодом синхронизации. Не меняй Rules трекера чтения или планировщика подарков по этой инструкции.

## 7. Что прислать для подключения

- Ссылку на сайт GitHub Pages.
- Объект `firebaseConfig` веб-приложения кино.
- UID своего пользователя из Firebase Authentication.
- Если всё-таки используем существующий проект планировщика: его текущие Firestore Rules вместо создания новой базы.

После этого нужно добавить код входа и синхронизации, ограничения по UID и проверить обмен между компьютером и iPhone. До этого момента одинаковая ссылка на двух устройствах НЕ означает общую коллекцию.

## 8. Установка на iPhone

1. Открой адрес GitHub Pages в Safari.
2. `Поделиться` → `На экран Домой`.
3. Если есть переключатель «Открывать как веб-приложение», включи его → `Добавить`.
4. Запускай с новой иконки. Пока облако не подключено, для переноса записей может понадобиться «Восстановить» и личный JSON: Safari и установленная PWA могут хранить данные раздельно.
5. Установится выбранная иконка № 2 «Кино с сердцем». Билет остаётся запасным вариантом.

## 9. Как обновлять проект

Загружай новые файлы интерфейса в тот же репозиторий и в те же папки через `Add file` → `Upload files` → `Commit changes`. Не удаляй репозиторий и не меняй адрес без необходимости. Перед большим обновлением сохраняй JSON-копию. При выпуске новой версии меняется версия service worker, чтобы обновился кеш оформления.
